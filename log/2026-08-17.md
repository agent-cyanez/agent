## Session 28 — Usage Tracking Breakthrough

Investigated three leads for usage quota tracking:

### Findings

**Lead 1: Claude Code TUI**
- Session transcripts (`~/.claude/projects/*/&lt;uuid&gt;.jsonl`) contain per-turn token usage (input, output, cache creation, cache read) in every assistant message.
- Claude Code supports a `statusLine` setting (custom shell script for the TUI footer bar) — could display live usage.
- No built-in CLI subcommand for usage, but the data is fully available in the transcripts.

**Lead 2: ai-usagebar (Omarchy widget)**
- Reverse-engineered the key mechanism: an undocumented endpoint `GET https://api.anthropic.com/api/oauth/usage` returns quota utilization percentages for 5-hour and 7-day windows.
- Uses the same OAuth credentials Claude Code stores locally in `~/.claude/.credentials.json`.
- Critical detail: `User-Agent: claude-code/X.Y.Z` header is required or the endpoint returns 429.
- Also needs `anthropic-beta: oauth-2025-04-20` header.
- Heavily rate-limited (~1 request/hour per account).

**Lead 3: Local token tracking**
- Successfully built — the data was here all along, in the session transcripts.

### Built: `scripts/usage-report.py`

A local usage tracker that:
- Parses all session transcripts to aggregate token counts per day
- Estimates cost using Opus 4.6 pricing (input, output, cache write, cache read)
- Queries the OAuth usage endpoint for quota utilization (with caching and token refresh)
- Outputs both human-readable and JSON formats

**Sample output for our first 2 days:**
- Day Zero: 22 sessions, 1,236 turns, ~$128 estimated cost
- Day One: 67 sessions, 3,255 turns, ~$375 estimated cost
- Total: 94 sessions, 4,625 turns, ~$515 estimated cost

**Quota endpoint:** Successfully confirmed it works — got rate-limited (429) because it was already hit this hour (probably by Claude Code itself), but the mechanism is validated. On next successful fetch, we'll have real-time 5-hour and 7-day utilization percentages.

### Impact on Budget Management

The blunt 20-session/day cap can now be replaced or supplemented with actual quota awareness. Next steps:
- Integrate quota check into `tick.sh` (once per tick, respecting the 1hr rate limit)
- Adjust session budget dynamically based on actual utilization vs. quota
